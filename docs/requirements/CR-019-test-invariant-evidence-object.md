# CR-019 测试不变量的判据对象归位

- 轨道: light
- 状态: 开发中
- 基线: edf1540
- 提出者: 用户（纯净克隆复现单项失败）

## 背景

`tests/test-role-guard-report.sh` 中一条 AC-06 断言在新克隆或未运行过 `/mh-dev`
的仓库里必然失败。该断言要证明的不变量是「mh-dev 的 `current_role` 恒为 planner」
（CR-017 D3 撤回理由的成立依据），但它取证的对象是 mh-dev 运行态 state 文件——
该文件被 `.gitignore` 排除，是流程产物而非不变量来源。

已实测：纯净克隆下套件 `497 | 通过 496 | 失败 1`，唯一失败项即此条，报
`current_role=''`；补齐该运行态文件后 497 项全绿。其余 17 个套件与框架自检均通过。

不变量的真实来源是两处受版本控制的实现：状态转移脚本在每次转移时硬写该值，
状态模板以同值初始化。断言挂在派生物上，使证据强度取决于「本机是否运行过
`/mh-dev`」这一与不变量无关的环境条件。

## 需求

- **R1** 该不变量的验证须取证于受版本控制的对象，使断言结论在任何环境下可复现，
  不依赖运行态文件是否存在。
- **R2** 运行态文件存在时仍应参与验证，作为「实现与产物一致」的补充证据；
  其缺失不得使套件失败，也不得降低 R1 所述结论的强度。
- **R3** 不变量有多个来源实现时须逐一取证；任一来源偏离该值即为失败。
- **R4** 本次改动不得降低套件既有覆盖（断言总数不减少），不得改动 role-guard
  及其他受治理脚本的行为。

## 非目标

- 不修改 `.gitignore` 对 mh-dev 运行态的排除规则
- 不改变 CR-017 D3 的撤回决定本身
- 不引入跳过计数机制——跳过使断言在新克隆内不验证任何东西，与 R1 相悖

## 影响范围

- `tests/test-role-guard-report.sh` — 判据对象替换（Tester 独占产出）
- `docs/requirements/CR-019-test-invariant-evidence-object.md` — 本文件
