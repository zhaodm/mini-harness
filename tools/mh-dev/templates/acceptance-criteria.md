# 验收标准

> `acceptance-criteria.json` 是机器门禁的权威 inventory；本文件为人工可读说明。
> 两个文件中的 ID 必须一致。

## 功能验收（AC）

> 针对需求的正向功能验证。每条必须有非空说明和可验证要求。

- AC-01: 描述要验证的功能、步骤与期望结果。
  - 验证方法: <命令或步骤>
  - 通过条件: <期望结果>

## 对抗性验收（AX，formal 必填）

> 针对边界值、错误路径、集成点、回归、隐含约束的破坏性验证。
> 每条必须具体到可执行（有明确的探测点和期望行为），不能留空或写"请补充"。

- AX-01 边界值: 验证输入/状态边界条件下的行为。
  - 探测点: <具体步骤>
  - 期望行为: <不变量>

- AX-02 错误路径: 验证异常/失败场景的处理。
  - 探测点: <具体步骤>
  - 期望行为: <不变量>

- AX-03 集成点: 验证与其他模块/角色的交互不变量。
  - 探测点: <具体步骤>
  - 期望行为: <不变量>

- AX-04 回归: 验证既有行为未被本次变更破坏。
  - 探测点: <具体步骤>
  - 期望行为: <不变量>

- AX-05 隐含约束: 验证未在需求中显式声明但由设计隐含的不变量。
  - 探测点: <具体步骤>
  - 期望行为: <不变量>
